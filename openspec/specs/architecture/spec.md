 架构规范

## 目的
本规范定义了苏铁微信小程序（SutWxApp）项目的技术架构，包括前端技术栈、后端服务、开发流程、安全设计、性能优化和监控策略。

## 技术栈

> 实际项目为**纯前端微信小程序**，使用 JavaScript 开发，不含后端服务与数据库。

### 前端技术栈
- **微信小程序框架**：原生微信小程序开发框架（WXML / WXSS / JS）
- **开发语言**：JavaScript（ES6+），不使用 TypeScript
- **UI**：自定义组件 + 全局 CSS 变量设计系统（Apple 极简风格）
- **开发工具**：微信开发者工具、VS Code
- **状态管理**：`utils/store.js` 轻量状态管理 + `wx.setStorageSync/getStorageSync` 本地持久化
- **路由管理**：微信小程序原生路由（`app.json` 声明）
- **网络请求**：`wx.request` API + `utils/request.js` 封装（拦截器、重试、LRU 缓存、请求取消、并发队列）
- **本地存储**：`wx.setStorageSync` / `wx.getStorageSync`
- **多语言**：gettext 风格 `.po` / `.pot` 文件

### 外部依赖（后端 API）
- 小程序通过 `services/*` 调用外部 REST API；基地址见 `app.js` 的 `globalData.baseUrl`。
- 认证方式：`Authorization: Bearer <token>`（见 `app.js` 的 `requestWithToken`）。

## 架构设计原则

系统遵循以下设计原则：

1. **模块化**：按业务域拆分 `services/`、`pages/`、`components/`、`utils/`，边界清晰
2. **高内聚，低耦合**：页面只负责视图与交互，业务逻辑下沉到 `services/`，通用能力沉淀到 `utils/`
3. **可扩展性**：新增业务域只需增加对应 Service 与页面，不改动核心请求层
4. **可靠性**：请求层内置重试、超时、取消与并发控制，降低弱网下的失败率
5. **安全性**：请求层内置 XSS 防护与 CSRF Token 处理；所有网络请求强制 HTTPS
6. **性能优化**：请求层 LRU 缓存避免重复请求，图片压缩工具降低包体与加载耗时
7. **一致性**：统一的命名、响应处理与错误格式
8. **文档化**：规范文档集中于 `openspec/`，便于团队对齐

## 系统分层结构

本小程序采用「视图层 — 服务层 — 工具层」的前端分层架构：

### 1. 视图层（pages + components）
- **作用**：渲染界面、处理用户交互、收集输入
- **技术**：WXML + WXSS + JS + 自定义组件
- **主要职责**：
  - 页面展示（首页、分类、商品、购物车、订单、用户、地址、设置、帮助）
  - 组件复用（商品卡片、空状态）
  - 交互反馈与本地状态

### 2. 服务层（services）
- **作用**：封装各业务域的网络请求，对视图层屏蔽接口细节
- **技术**：`utils/request.js` + 业务 Service
- **主要职责**：
  - 认证（authService）
  - 商品与分类（productService / categoryService）
  - 购物车（cartService）
  - 订单（orderService）
  - 地址（addressService）

### 3. 工具层（utils）
- **作用**：提供跨业务复用的基础能力
- **技术**：纯 JS 模块
- **主要职责**：
  - 网络请求封装（request.js：拦截器、重试、LRU 缓存、取消、并发队列）
  - 格式化（format.js：价格、日期等）
  - 监控上报（monitor.js）
  - 状态管理（store.js）
  - 图片压缩（compress-images.js）

## 核心模块架构

### 用户模块
- **结构**：`pages/user` + `services/authService` + 本地存储
- **主要功能**：登录（`wx.login`）、用户信息获取、Token 与用户信息持久化

### 商品模块
- **结构**：`pages/home`、`pages/category`、`pages/product` + `productService` / `categoryService`
- **主要功能**：商品列表、分类浏览、商品详情、推荐展示

### 购物车模块
- **结构**：`pages/cart` + `cartService`
- **主要功能**：加入购物车、数量调整、价格计算、结算

### 订单模块
- **结构**：`pages/order/*` + `orderService`
- **主要功能**：订单列表、订单详情、订单确认、状态跟踪

### 地址模块
- **结构**：`pages/address`（分包）+ `addressService`
- **主要功能**：收货地址增删改查

## 数据关系设计

前端关注的数据实体及其关系：

- 用户 → 多个地址（一对多）
- 用户 → 多个订单（一对多）
- 订单 → 多个订单项（一对多）
- 商品 → 所属分类（多对一）
- 订单项 → 关联商品（多对一）

> 以上实体由外部后端持久化；前端仅通过 Service 读取与提交，本地仅缓存 Token、用户信息、购物车等轻量数据。

## 安全设计

### 认证与授权
- **Bearer Token 认证**：
  - 登录后服务端返回 Token，前端存入 `wx.setStorageSync("token")`
  - 请求层在 `Authorization` 头携带 `Bearer <token>`
  - 收到 `401` 时清空本地数据并跳转首页重新登录

- **本地凭证保护**：
  - Token、openid、userInfo 仅存于微信安全存储，不写入日志

### 数据安全
- **传输安全**：所有请求通过 HTTPS（见 `app.json` 的 `urlCheck`）
- **输入校验**：请求层对输入输出做 XSS 防护与基础校验
- **CSRF 防护**：请求层内置 CSRF Token 获取与携带机制

### 网络安全
- **请求域名校验**：微信小程序要求 request 合法域名在后台配置
- **超时与重试**：默认 10s 超时，失败自动重试 1 次，降低弱网失败率

## 性能优化

### 前端性能
- **请求缓存**：`utils/request.js` 提供 LRU 缓存（默认 50 条，5 分钟 TTL），避免重复请求
- **并发控制**：请求队列默认最大并发 5，防止请求风暴
- **图片压缩**：`utils/compress-images.js` 压缩上传图片，降低流量与包体
- **分包加载**：地址、设置、帮助页放入 `subpackages`，减小主包体积

### 资源优化
- **按需加载**：分包页面独立加载
- **本地缓存**：Token 与购物车状态本地持久化，减少启动请求

## 部署设计

微信小程序通过微信开发者工具「上传代码」后，在微信公众平台提交审核并发布：

1. 开发者本地构建与预览
2. 微信开发者工具上传代码包
3. 公众平台提交审核
4. 审核通过后发布上线

> 小程序无独立服务器部署；后端服务由对应团队独立部署与运维。

## 监控与运维

### 应用监控
- `utils/monitor.js` 统一捕获全局错误（`onError`、`onUnhandledRejection`）并上报
- 关注指标：请求成功率、平均响应时间、JS 错误率

### 日志管理
- 开发期通过 `console` 输出带 `[模块]` 前缀的日志便于定位
- 生产期由 `monitor.js` 收敛并上报，避免敏感信息泄露

### 告警与故障处理
- 关键错误经 `monitor.js` 上报至监控后端
- 请求层对 `401` 做自动登出处理，对网络异常做友好提示

## 架构评估

- **清晰的层次**：视图 / 服务 / 工具三层职责分明
- **高可扩展性**：新增业务域低成本接入
- **强可靠性**：请求层内置重试、超时、取消、缓存
- **良好安全性**：HTTPS、Token 认证、XSS/CSRF 防护
- **良好性能**：LRU 缓存、并发控制、图片压缩、分包
- **易维护**：模块化组织，命名与规范统一
