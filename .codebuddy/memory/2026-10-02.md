## request 测试 15 失败根因
### 真实实现缺陷（应修代码）
1. `utils/request-api.js:89`：401 分支 `navigateTo` 跳 `/pages/home/index`，应为 `/pages/login/login`（与"清 token 跳登录"语义冲突）→ 真实功能 bug
2. `utils/request.js:39-54`：默认 `needAuth!==false` 且无 token 时强制 `throw 未授权`，阻断商城公开端点（product/category/post list 免登录）的匿名请求；测试期望匿名可访问 → 真实设计缺陷

### 测试契约/mock 错误（应修测试）
3. 模块级 `requestInterceptors`/`responseInterceptors` 数组在用例间不重置 → 第二 describe 批量被残留拦截器污染，报"请求失败：未知状态"
4. 重试/无网络测试用 `jest.fn().mockRejectedValue` 不触发 `options.fail` 回调（请求层是回调制）→ 超时；应改 `mockImplementation(cb => cb.fail(err))`
5. 错误对象契约：实现 `reject(new Error(...))` 包装，测试 `rejects.toEqual({errMsg})` 期望原对象
6. 500 文案：实现硬编码"服务器内部错误"优先于"请求失败：500"，测试期望过期
