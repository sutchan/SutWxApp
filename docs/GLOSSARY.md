# 术语表

> **文档版本**: v1.1.0
> **更新时间戳**: 2026-11-07
> **对齐版本**: 小程序 `3.5.16` · WordPress 插件 `0.7.1`
> **用途**: 统一项目内同一概念的标准叫法。文档、代码注释、提交信息、任务描述中涉及下列概念时，一律使用本表的标准术语；历史文档中的其它叫法不再沿用。

---

## 1. 端与形态

| 标准术语 | 说明 | 不再使用 |
|----------|------|----------|
| **小程序端** | `SutWxApp/` 目录下的微信小程序工程 | 前端 / 客户端 / App 端 |
| **插件端** | `sutwx-app-api/` 目录下的 WordPress 插件 | 后端 / 服务端 |
| **内容源** | WordPress + WooCommerce 承载的数据与订单 | 数据库 / 后端服务 |
| **原型** | `prototype/` 下浏览器直接打开即可交互的单文件 HTML | 原型站 / Demo 站 |
| **站点产物** | `build.js` 由原型生成的根目录 HTML（`index.html` 等） | 静态站 / 构建目录 |

## 2. 接口与数据

| 标准术语 | 说明 | 不再使用 |
|----------|------|----------|
| **端点** | 插件注册的 REST 路由，如 `/api/product/list` | 接口地址 / API 路径 |
| **包络** | 后端统一响应结构 `{code, message, data, timestamp, requestId}` | 响应包装 / 信封 |
| **解包（unwrap）** | 前端从包络中取出 `data` 的过程（`utils/api.js`） | 拆包 / 取 data |
| **列表包络** | `data` 为 `{list, total, page, pageSize}` 的分页结构 | 分页结构 |
| **DTO** | 后端映射后输出给小程序的数据结构 | VO |
| **字段漂移** | 前后端 DTO 字段不一致 | 契约漂移 |
| **契约校验** | `npm run check:contract` 对前后端字段与分页包络的自动比对 | 契约测试 |

## 3. 身份与安全

| 标准术语 | 说明 | 不再使用 |
|----------|------|----------|
| **openid** | 微信用户在本应用下的唯一标识 | 用户 ID / 用户名 |
| **登录态** | 小程序本地持有的令牌对及其有效性状态 | 登录状态 |
| **令牌** | JWT access token 与 refresh token | token / 票据 |
| **黑名单** | 登出后被拒绝的令牌 `jti` 集合 | 失效列表 |
| **归属校验** | 按 `openid` 校验资源归属，防止越权 | 权限校验 / RBAC（本项目无角色体系） |
| **限频** | 按 IP 的请求频率限制 | 限流 / 防刷 |
| **密钥治理** | 对 JWT 密钥等敏感配置的存储与轮换管理 | 密钥管理 |

## 4. 商品与交易

| 标准术语 | 说明 | 不再使用 |
|----------|------|----------|
| **商品** | WooCommerce Product | 产品（代码字段名 `productId` 不变） |
| **文章** | WordPress Post | 帖子 / 内容 |
| **分类** | WooCommerce Product Category | 品类（类目特指微信后台经营类目） |
| **订单状态** | 数字码：`0` 已取消 / `1` 待付款 / `2` 待发货 / `3` 待收货 / `4` 已完成 / `5` 已退款 | 状态字符串（`pending`/`paid` 等为 WooCommerce 原值，仅出现在映射表中） |
| **下单** | 创建订单 | 提交订单 |
| **发货** | 商家标记订单已发出（`/api/order/ship`） | 配送 / 出库 |
| **掉单** | 已支付但订单状态未更新 | 支付丢失 / 状态不同步 |
| **预支付** | 服务端向微信支付下单并返回调起参数 | 统一下单 |
| **查单** | 以商户订单号查询支付状态 | 订单查询 |

## 5. 运行时与工程

| 标准术语 | 说明 | 不再使用 |
|----------|------|----------|
| **门禁** | 提交前必须通过的自动检查（lint / check / test） | 流水线检查 |
| **配置校验** | `npm run check:config`（页面四件套、路由、tabBar 图标） | — |
| **版本校验** | `npm run check:version`（四处版本号一致） | — |
| **监控** | 小程序端性能与错误采集上报（`utils/monitor*.js`） | 埋点（业务埋点另称行为上报） |
| **可观测性** | 服务端日志、错误上报、拨测、健康检查的总称 | 监控（与服务端侧区分） |
| **联调** | 与真实 WooCommerce 站点 / 微信支付环境对接验证 | 对账 |
| **体验版** | 上传至微信后台、供审核前体验的版本 | 测试版 |
| **拆分** | 将超过 200 行的文件按职责拆为 trait / 独立类 / 子模块 | 重构（泛指重构时用「重构」） |

### 5.1 近期新增概念（3.5.11 ~ 3.5.16）

| 标准术语 | 说明 | 不再使用 |
|----------|------|----------|
| **八项门禁** | `npm run check` 串联 version / config / images / ids / contract / bundle / plugin-version / docs 八项校验 | 三件套 / 三项门禁 |
| **资源门禁** | `check:images` 校验 WXML 中所有 `/images/*` 引用真实存在（微信 `image` 不支持 SVG） | 图片检查 |
| **语义化 ID 门禁** | `check:ids` 校验 WXML 根容器带语义化 id 且全量唯一 | — |
| **自动发布** | `auto-release.yml` 在 CI 五 Job 全绿后按版本号自动创建并推送 Tag，`release.yml` 接续打包发版 | 手动打 Tag（仅作补发兜底） |
| **健康拨测** | `health-probe.yml` 每 5 分钟探测 `/api/health`，失败推送企业微信机器人 | — |
| **隐私保护指引** | 微信《小程序用户隐私保护指引》机制：`utils/privacy.js` 前置授权 + `pages/privacy/` 授权页 | 隐私浏览开关（旧伪开关已移除） |
| **环境配置表** | `utils/env.js` 按 develop / trial / release 自动注入 baseUrl | 手工改 `globalData.baseUrl` |
| **幂等短锁** | 下单以 `clientRequestId` 做 10 秒去重，失败路径均释放锁 | 防重复提交 |
| **掉单兜底** | `Sutwx_Pay_Cron` 每 5 分钟查单同步支付状态 | 支付状态补偿 |
| **锁文件** | `SutwxApp/package-lock.json` 已入库，本地与 CI 统一 `npm ci` | 无锁安装 / `npm install`（根站点 Job 除外） |

## 术语使用约定

1. 文档正文、代码注释、提交信息、任务描述中涉及上述概念时使用**标准术语**列的词。
2. 历史文档（`CHANGELOG.md`、归档任务记录）中的旧叫法**保留原样**，属历史记录，不做回改。
3. 代码标识符不因术语统一而重命名：`productId`、`userInfo` 等字段名保持与后端契约一致。
4. 新增概念时，先在本表登记标准术语，再在文档中使用。
